# MLOps Architecture

## Stages

1. `data_pipeline`
   Builds a reproducible dataset package from `Data/Base Final1.csv`.
   Artifacts include raw snapshot, processed modeling dataset, feature list, schema, profile, manifest and ingestion summary.

2. `trainer`
   Consumes a packaged dataset directory, trains the configured model sequence and logs both the model and the data contract into MLflow.

3. `drift_monitor`
   Compares a current dataset against the packaged baseline, writes drift artifacts and can trigger retraining when thresholds are exceeded.

4. `api`
   Serves the champion model from MLflow Registry through FastAPI.

5. `app`
   Streamlit client for manual exploration, prediction and explanation workflows.

6. `airflow`
   End-to-end orchestration layer that coordinates data packaging, bootstrap training, drift checks, conditional retraining, inference artifacts and API smoke tests.

## Data Contract

The dataset package generated by `scripts/package_data.py` has this structure:

```text
artifacts/data/base_final_package/
├── raw/
│   └── base_final_snapshot.csv
├── processed/
│   └── modeling_dataset.csv
└── metadata/
    ├── manifest.json
    ├── feature_list.txt
    ├── feature_manifest.json
    ├── schema.json
    ├── profile.json
    └── ingestion_summary.md
```

Key guarantees:

- `manifest.json` stores the exact feature build configuration and dataset fingerprints.
- `feature_list.txt` is the canonical feature contract for training and serving.
- `processed/modeling_dataset.csv` is the exact dataframe expected by the trainer.
- Drift monitoring regenerates the current dataset with the same feature build config before comparing it.

## Airflow Readiness

These interfaces are now scheduler-friendly:

- `scripts/package_data.py`
- `scripts/train.py --data-package-dir ...`
- `scripts/check_drift.py --reference-dir ... --current-data ...`
- `scripts/promote_data_package.py --source-dir ... --target-dir ...`
- `scripts/api_smoke_test.py --api-base-url ... --input ...`

The main DAG `dags/colombia_tourism_mlops_dag.py` already maps directly to those tasks with file-based handoffs through `artifacts/` and MLflow as the model registry/control plane.
